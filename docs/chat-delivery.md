# Chat delivery status

Inspected actual schema.sql, platform_schema.sql, session authentication/CSRF middleware, staff portal, header rendering and provider delivery paths. Production health reported 0.12.7-rc5. GitHub main still points at 0.12.7-rc4; this work builds on the already-tested rc5 source without discarding it.

Stage 1 foundation: private member-scoped team conversations, idempotent DMs, named groups, active staff directory/search, bounded paginated history, monotonic read markers, unread header badge, audit metadata, retry-safe message sending and per-user send throttling. Desktop dialog drawer and mobile full-screen layout. Plain text is escaped; no client Inbox, provider, booking or accounting write is performed. Membership is required even for owners. Current transport is three-second foreground polling, not SSE/WebSocket. Clients/AI tabs are explicit unavailable states, not working features.

Not production-ready or deployed. Still required in Stage 1: authorized attachment upload/download and malware/size controls, mentions, persistent real-time transport with session revocation, group membership lifecycle, offline notification consent/providers, browser/mobile accessibility tests, broader adversarial security tests, retention policy and administrator support procedure. Existing job links must continue enforcing target-page permissions; chat must never preview unauthorized job data.

Stages 2–5 remain unimplemented. Reuse client account/service mappings, existing Gmail outbound approval/idempotency paths and secure portal. Add SMS only after an actual approved provider and consent policy are established. Human/AI authorship and provider delivery status must be durable. Keep AI disabled until approved policy versions, authenticated tool scopes, human takeover and approval records exist. Date-change proposals must preserve the accepted quote, compare approved current pricing, route reductions and increases through staff/client review, and atomically recheck availability on application. Final confirmation must add the requested verified human-call gate to existing deposit/capacity checks; current deposit confirmation code must be reviewed before any automated use. No direct card collection or AI payment verification.
